1. 개요

한 줄 정의 — 커피를 마신 뒤 원두 정보, 추출 레시피, 오각형 맛 프로필, 플레이버 태그, 후기와 점수를 남기는 iOS 테이스팅 노트 앱.

목적

  • 종이 테이스팅 노트를 대체하면서, 종이로는 어려운 같은 원두의 시간에 따른 변화(D+N)와 레시피 재사용을 지원한다.
  • 컵 노트를 표준화된 플레이버 태그로 쌓아, 이후 커뮤니티 기능에서 누구나 이해할 수 있는 정보로 공유할 기반을 만든다.
  • 신입 iOS 포트폴리오: SwiftUI + MVVM, Firebase, 직접 그린 오각형 차트, 1:N 데이터 모델 설계를 보여준다.

주요 사용자

홈카페에서 핸드드립·에스프레소를 즐기며 원두별 기록을 남기고 싶은 사람. 1차 사용자는 개발자 본인.

플레이버 태그

#항목결정
D7태그 체계SCA·WCR 플레이버휠을 참고한 자체 한국어 분류(부록, flavor_taxonomy.json 110개 노드). 각 태그에 영문 표준 용어(refTerm)를 매핑. 휠 자체의 구조·디자인·번역은 쓰지 않음
D33SCA 문의문의하지 않고 진행. 앱 안 안내 문구는 "참고해 자체 구성"으로 표기하고 SCA 로고·휠 이미지는 쓰지 않음
D8선택 깊이1·2·3단계 어느 노드든 선택 가능
D13사용자 정의 태그만들 수 없음. 체계에 없는 향미는 "향미 메모" 텍스트에 기록
D14태그 개수프레그런스 태그, 컵 노트 태그 각각 최대 10개
D15상하위 동시 선택하위를 고르면 그 조상은 자동 해제, 조상을 고르면 그 자손은 자동 해제(각 목록 안에서)
D43태그 목록 수정출시 전이므로 ID까지 수정(v1.1): roast.grain.grain 삭제(상위 "곡물"과 중복), fruit.orchard를 fruit.pome("사과·배")와 fruit.grape("포도", 하위 "청포도")로 분리, defect.sour 이름 "과한 신맛", sweet.caramel의 refTerm은 Caramelized 유지. 첫 출시 이후에는 ID를 바꾸지 않음
D34상위 태그 필터"베리"로 필터하면 "블루베리" 노트도 나옴. 노트 저장 시 두 태그 목록과 각 조상 ID를 합친 tagIndex를 함께 저장해 array-contains 쿼리 (v1.0, Q3 해결)

원두·레시피·장비

#항목결정
D27장비드리퍼(추출 기구)·그라인더를 내 장비로 등록하고 레시피에서 선택. 추출 방식은 별도 항목. 분쇄도 단위는 그라인더 설정을 따름

D35아이스/핫레시피에 온도 구분 serving: hot | iced(선택)만 기록. 얼음량은 기록하지 않음 (v1.0, Q4 해결)

D30블렌드원두에 구성 원두 목록(국가·지역·품종·가공방식·비율). 싱글 오리진은 구성 1개
D32블렌드 규칙구성 최대 5개. 구성이 2개 이상이면 "비율 모름" 토글 제공(기본 꺼짐). 꺼져 있으면 모든 구성에 비율이 있어야 하고 합이 100%, 켜져 있으면 비율을 저장하지 않음 (v1.0 변경)

6. 비즈니스 규칙

R1. D+N 계산

  • N = drankOn − bean.roastDate (일 단위, DateOnly 간 차이). 로스팅 당일은 D+0.
  • roastDate가 nil이면 D+N 배지를 표시하지 않는다.
  • 표시 형식: D+14. N이 음수인 노트는 저장할 수 없다(R3 참고).
  • 원두의 로스팅일을 나중에 고치면, 그 원두의 모든 노트 D+N은 화면에서 다시 계산된다(저장하지 않는 값).

R2. 이전 레시피 불러오기

  • 새 노트에서 원두를 선택하면, 같은 beanId의 노트 중 drankOn 내림차순, 같으면 createdAt 내림차순으로 첫 노트의 recipe를 복사한다.
  • 복사 대상은 레시피(추출 방식, 핫/아이스, 장비, 분쇄도, 수치)만이다. 오각형·태그·점수·후기는 복사하지 않는다.
  • 복사한 레시피의 장비가 이미 삭제됐으면 그 장비 칸은 비우고 나머지만 채운다.
  • 같은 원두의 노트가 없으면 레시피는 비워 둔다.
  • 불러오면 레시피 섹션 위에 "11월 10일 레시피를 불러왔어요 · 비우기" 배너를 보여준다. "비우기"를 누르면 레시피 필드를 모두 지운다.
  • 사용자가 레시피를 직접 수정한 뒤 원두를 다른 것으로 바꾸면, 덮어쓰기 전에 확인 알림을 띄운다.
  • 편집 모드(기존 노트 수정)에서는 불러오지 않는다.

R4. 점수

  • 표시: 항상 소수 둘째 자리까지 (86.25, 88.00).
  • 점수순 정렬: 점수 내림차순 → 동점이면 마신 날 내림차순 → 작성 시각 내림차순. 점수가 null인 노트는 맨 아래, 그 안에서는 최신순(마신 날 → 작성 시각 내림차순).
  • 정렬은 기기의 전체 노트로 계산한다(D20). Firestore 쿼리에 의존하지 않으므로 별도 인덱스가 없다.
  • 화면 이름은 항상 "내 점수"(D6).

R5. 플레이버 태그

  • 1·2·3단계 어느 노드든 선택할 수 있다(D8).
  • 자식 노드를 선택하면 그 조상 노드의 선택은 해제된다. 조상 노드를 선택하면 그 자손 노드의 선택은 해제된다(D15).
  • 프레그런스 태그와 컵 노트 태그는 서로 독립이다. 같은 태그를 양쪽에 고를 수 있고, 상하위 규칙(D15)과 10개 제한(D14)은 각 목록 안에서만 적용한다.
  • 노트에 표시할 때는 각 목록을 선택 순서대로 보여준다.
  • 태그 필터(D34)는 tagIndex array-contains 선택한 ID로 찾는다. "베리"로 필터하면 프레그런스나 컵 노트에 "베리", "블루베리", "라즈베리" 등이 있는 노트가 모두 나온다. "블루베리"로 필터하면 "베리"만 고른 노트는 나오지 않는다.
  • taxonomy가 바뀌어 조상 관계가 달라지면 tagIndex 마이그레이션(R11)을 실행한다.
  • 선택 화면(G)과 태그 검색에는 isSelectable인 노드만 보여준다. deprecated 태그가 붙은 기존 노트는 그대로 표시하고, 편집할 때 사용자가 직접 지우기 전에는 유지한다.

R6. 삭제와 확인

  • 사용자가 직접 고른 파괴적 동작(삭제, 변경 사항 버리기, 계정 삭제)은 alert가 아니라 확인 대화상자(.confirmationDialog, 액션 시트)로 확인한다. 파괴적 버튼은 role: .destructive, 취소 버튼은 시스템 기본 제공.
  • 노트 삭제: "노트 삭제" 확인 후 삭제, 되돌릴 수 없다.
  • 원두 삭제: 연결된 노트가 있으면 메시지 "노트 N개도 함께 삭제돼요"와 함께 확인 후 원두와 노트를 배치로 삭제한다.
  • 예상하지 못한 문제를 알릴 때(저장 실패, 계정 연결 실패)만 alert를 쓴다.
  • 변경 사항이 있는 시트 닫기(D40): 변경 사항 판단은 시트를 연 시점의 값과 현재 값 비교(Equatable). 변경이 있으면 스와이프는 막히고, 스와이프 시도 또는 "취소" 탭 모두 같은 확인 메뉴("변경 사항 버리기" destructive / "계속 편집")를 띄운다. 변경이 없으면 둘 다 바로 닫힌다. 시트 안에서 E·F·G·K·L로 push했다 돌아와도 입력값은 유지된다(작성 상태는 D의 ViewModel이 소유).

  5. 4가 실패하면 앱 실행·포그라운드 진입 때마다 Keychain 티켓으로 재시도한다(멱등). 사용자 화면에는 영향이 없다. 30일 안에 성공하지 못하면 Crashlytics 비치명 오류로 기록한다.
  • 로그아웃하면 새 익명 계정으로 빈 상태에서 시작한다. 로그아웃 전에 확인 대화상자로 이 점을 알린다.

R8. 보관 안내 카드 (D25)

  • 조건: 익명 상태 + 노트 저장 직후 전체 노트 수가 1개 또는 10개에 도달.
  • 각 단계(first, tenth)마다 한 번만 표시. 닫으면 그 단계는 다시 표시하지 않음. 상태는 사용자 문서 backupPromptDismissed: [String]에 저장.
  • 10개째 문구: "노트가 10개 쌓였어요. Apple 계정에 보관해 두면 기기를 바꿔도 남아요."
  • Apple 연결 상태에서는 표시하지 않는다.

R10. 데이터 삭제 (D21, D42)

  • 모든 삭제는 Cloud Function이 재귀 삭제(firestore.recursiveDelete(users/{uid}))로 수행한다. 대상: 사용자 문서와 하위 컬렉션 beans, notes, gear 전체.
  • 함수는 멱등이다. 중간에 끊겨도 같은 호출을 다시 하면 남은 문서를 지우고, 이미 없으면 성공으로 응답한다.
  • 앱 쪽 계정 삭제 순서: (Apple 연결 시) Apple 재인증 → 토큰 철회 → deleteAccount 호출(데이터 재귀 삭제 후 Admin SDK로 Auth 사용자 삭제) → 로컬 Firestore 캐시 비우기(clearPersistence) → 새 익명 계정으로 빈 B.
  • 재시도: 호출 전에 Keychain에 pendingDeletion = uid를 기록하고 성공 후 지운다. 실패하면 alert "삭제를 마치지 못했어요" + "다시 시도". 앱을 다시 열었을 때 pendingDeletion이 있으면 B 대신 "계정 삭제를 마무리하고 있어요" 화면을 보이고 자동 재시도한다.
  • Apple 서버 알림(appleServerNotifications): Apple JWS 서명 검증 → sub로 Firebase 사용자 조회 → consent-revoked, account-deleted면 재귀 삭제 + Auth 삭제, email-enabled/disabled는 기록만. 같은 알림이 여러 번 와도 결과가 같아야 한다(멱등).

R11. 태그 체계 마이그레이션

  1. 실행 조건: 번들 JSON의 version > 사용자 문서 taxonomyVersion, 온라인 상태, 앱 포그라운드. 오프라인이면 다음 포그라운드로 미룬다.
  2. 대상: 기기에 이미 구독 중인 전체 노트(D20)에서 새 taxonomy로 다시 계산한 tagIndex가 저장값과 다른 노트만.
  3. 쓰기: 400개씩 WriteBatch(한도 500보다 여유). 각 배치는 tagIndex와 updatedAt만 바꾼다.
  4. 재개: 진행 커서가 필요 없다. 다시 실행하면 "다른 노트만" 다시 계산하므로 남은 것만 처리된다(멱등). 배치 실패 시 지수 백오프로 3회 재시도 후 다음 실행으로 미룬다.
  5. taxonomyVersion은 모든 대상 노트가 성공한 뒤에만 갱신한다. 중간에 앱이 종료돼도 다음 실행에서 1부터 다시 판단한다.
  6. 마이그레이션 중에도 앱은 정상 사용 가능. 태그 필터 결과는 마이그레이션 완료 전까지 일부 부정확할 수 있다.

7. Firestore 구조

users/{uid}
  ├─ createdAt: Timestamp
  ├─ backupPromptDismissed: [String]   ← R8
  ├─ taxonomyVersion: Int              ← R11
  ├─ beans/{beanId}      ← Bean (origins 배열 포함)
  ├─ notes/{noteId}      ← Note (beanId 필드로 원두 참조)
  └─ gear/{gearId}       ← Gear (드리퍼·그라인더)
cleanupTickets/{ticketId}   ← 서버 전용(클라이언트 접근 금지). anonUid, expiresAt(TTL 정책 30일)
  • 노트를 원두 하위 컬렉션이 아니라 사용자 하위에 평평하게 둔다.
  • 앱은 beans, notes, gear 세 컬렉션 전체를 스냅샷 리스너로 구독하고(D20), 원두 이름 조인·정렬·검색·필터·원두별 노트·R2 레시피 불러오기를 모두 메모리의 전체 데이터로 처리한다.
  • 규모 가정: 노트 3,000개 이하, 원두 수백 개. 노트 1개는 약 1~2KB라 전체 수 MB 수준. 이 가정을 넘는 사용자가 생기면 v2에서 페이지네이션+서버 검색을 다시 검토한다.
  • 날짜(DateOnly)는 "yyyy-MM-dd" 문자열로 저장해 시간대 문제를 피한다. 문자열 정렬이 날짜 정렬과 같다.

쿼리와 인덱스

D20에 따라 화면용 쿼리는 컬렉션 전체 구독 3개뿐이며 복합 인덱스가 필요 없다. tagIndex는 기기에서 필터할 때 쓰고, 향후 서버 쿼리(array-contains)에도 그대로 쓸 수 있게 유지한다.

보안 규칙 (값 검증 포함, v1.1)

rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    function isOwner(uid) { return request.auth != null && request.auth.uid == uid; }
    function optStr(d, k, max) { return !(k in d) || d[k] == null || (d[k] is string && d[k].size() <= max); }
    function strReq(d, k, max) { return k in d && d[k] is string && d[k].size() >= 1 && d[k].size() <= max; }
    function tags(d, k) { return d[k] is list && d[k].size() <= 10; }
    function axis(v) { return v is int && v >= 1 && v <= 5; }

    function validNote(d) {
      return d.keys().hasOnly(['beanId','drankOn','recipe','profile','fragranceTagIds','cupTagIds','tagIndex',
                               'flavorMemo','review','score','rebuy','createdAt','updatedAt'])
        && strReq(d, 'beanId', 128)
        && d.drankOn is string && d.drankOn.matches('^[0-9]{4}-[0-9]{2}-[0-9]{2}$')
        && tags(d, 'fragranceTagIds') && tags(d, 'cupTagIds')
        && d.tagIndex is list && d.tagIndex.size() <= 60
        && (d.score == null || (d.score is number && d.score >= 0 && d.score <= 100))
        && (!('rebuy' in d) || d.rebuy == null || d.rebuy in ['yes','maybe','no'])
        && (!('profile' in d) || d.profile == null ||
            (axis(d.profile.aroma) && axis(d.profile.acidity) && axis(d.profile.sweetness)
             && axis(d.profile.aftertaste) && axis(d.profile.body)))
        && optStr(d, 'flavorMemo', 200) && optStr(d, 'review', 1000);
    }
    function validBean(d) {
      return strReq(d, 'name', 60) && strReq(d, 'roastery', 40)
        && d.origins is list && d.origins.size() <= 5
        && d.isFinished is bool && d.blendRatioUnknown is bool
        && optStr(d, 'roasteryNotes', 200);
    }
    function validGear(d) {
      return d.kind in ['brewer','grinder'] && strReq(d, 'name', 40) && optStr(d, 'memo', 100);
    }

    match /users/{uid} {
      allow read, write: if isOwner(uid);
      match /notes/{id} { allow read, delete: if isOwner(uid);
                          allow create, update: if isOwner(uid) && validNote(request.resource.data); }
      match /beans/{id} { allow read, delete: if isOwner(uid);
                          allow create, update: if isOwner(uid) && validBean(request.resource.data); }
      match /gear/{id}  { allow read, delete: if isOwner(uid);
                          allow create, update: if isOwner(uid) && validGear(request.resource.data); }
    }
    match /cleanupTickets/{id} { allow read, write: if false; }
  }
}

0.25 단위, 비율 합 100% 같은 계산 규칙은 규칙 언어로 표현하기 어려워 클라이언트 NoteRule/BeanRule에서 검증한다. 규칙은 Firebase Emulator 테스트로 검증한다(test-plan TST-S01~).

  • 태그 필터는 검색 토큰으로 보이고, 텍스트 검색과 함께 쓸 수 있다
  • 원두의 로스팅일이 없으면 D+N 배지가 보이지 않는다
  • 보관 안내 카드는 첫 노트와 10번째 노트 저장 후에 각각 한 번 나타나고, 닫으면 그 단계는 다시 나타나지 않는다
  • "베리"로 필터하면 블루베리 태그가 있는 노트도 나온다

C노트 상세

목적

한 잔의 기록을 종이 노트처럼 한눈에 본다.

구성 (위→아래, ScrollView)

  1. 헤더: 원두 이름(NavigationLink → I), 로스터리 · 원산지 요약(Origin 표시 규칙), 로스팅일 / 마신 날 / D+N
  2. 내 점수(크게, 라벨 "내 점수") + 재구매 의향(읽기 전용 표시). 동기화 대기 중이면 헤더 오른쪽에 구름 아이콘(R9)
  3. 오각형(160pt) + 축별 값 표
  4. 향과 맛: "프레그런스" 태그 줄, "컵 노트" 태그 줄(계열 색상 칩), 향미 메모, 로스터리 노트(원두에서 가져옴, 보조 색)
  5. 추출 레시피 카드: 추출 방식(아이스면 "아이스" 배지) · 드리퍼 · 그라인더와 분쇄도("코만단테 C40 · 22클릭") · 원두량/물량 · 비율 · 온도 · 시간
  6. 후기

비어 있는 섹션은 숨긴다. Large Title을 쓰지 않고 inline 제목(원두 이름 줄임)을 쓴다.

동작

  • 툴바: "편집" 버튼 → D(편집 모드, 시트), Menu(ellipsis.circle): "이 레시피로 새 노트" → D(시트), "삭제"(destructive) → R6

수용 기준

  • 입력하지 않은 섹션은 화면에 나타나지 않는다
  • 원두 이름을 탭하면 그 원두의 상세(I)로 간다
  • "이 레시피로 새 노트"는 이 노트의 레시피를 채운 새 노트를 연다

D노트 작성 / 편집 (시트)

목적

한 화면에서 노트의 모든 항목을 입력한다. 필수는 원두와 마신 날뿐이다.

표시 방식

  • .sheet(large detent) 안에 NavigationStack + Form. 제목 "새 노트" / "노트 편집"(inline)
  • 툴바: 왼쪽 "취소"(.cancellationAction), 오른쪽 "저장"(.confirmationAction, 굵게)
  • 변경 사항이 있으면 스와이프 닫기를 막고, 스와이프 시도나 "취소" 모두 확인 메뉴 "변경 사항 버리기"(destructive) / "계속 편집"(D40, R6)

구성 (Form 섹션 순서)

  1. 원두: "원두" 행(NavigationLink, 선택값 표시) → E push. 마신 날 DatePicker(.compact, 기본 오늘, 미래 불가). 원두에 로스팅일이 있으면 행 오른쪽에 D+N
  2. 추출 레시피: R2 배너(섹션 상단 행) → 추출 방식(Picker 메뉴), 핫/아이스(Picker(.segmented): 선택 안 함 / 핫 / 아이스), 드리퍼 행·그라인더 행(NavigationLink → K 선택 모드, 선택값 표시), 분쇄도(TextField, 선택한 그라인더의 단위를 trailing 보조 텍스트로 "클릭"), 원두량 g, 물량 g(TextField + .keyboardType(.decimalPad) / .numberPad, 단위는 trailing 보조 텍스트), 비율(읽기 전용 LabeledContent), 물 온도 ℃, 추출 시간(분·초 Picker 2열 휠)
  3. 맛 그래프: 꺼져 있으면 "맛 그래프 추가" 버튼 행. 켜면 오각형(200pt) + 축 5행, 각 행에 1~5 세그먼트(세그먼트당 44×44pt 이상). 섹션 footer에 "지우기" 버튼
  4. 향과 맛: "프레그런스" 태그 행, "컵 노트" 태그 행(각각 선택된 칩 표시, 탭 → G push, G 제목도 같은 이름), 향미 메모(TextField(axis: .vertical), 플레이스홀더 "태그에 없는 향과 맛")
  5. 평가: 내 점수(꺼져 있으면 "내 점수 추가"; 켜면 정수 Picker(.wheel) + .00/.25/.50/.75 Picker(.segmented)), 재구매(Picker(.segmented): 선택 안 함 / O / △ / X — VoiceOver 라벨 "다시 살래요 / 고민돼요 / 안 살래요"), 후기(여러 줄)

동작

  • 저장 시 검증 실패 → 해당 행으로 스크롤 + 행 아래 오류 텍스트 + 오류 햅틱. "저장" 버튼은 비활성화하지 않음
  • 저장 성공 → 시트 닫힘. 작성 모드는 B에서 C로 push, 편집 모드는 C 갱신
  • 진입 경로별 초기값: B "새 노트" → 빈 노트 / I "이 원두로 노트 쓰기" → 원두 선택 + R2 / C "이 레시피로 새 노트" → 원두 + 그 노트의 레시피
  • 키보드 툴바에 "완료" 버튼(숫자 키패드에 리턴 키가 없으므로)

상태

  • 저장 중: "저장" 자리에 ProgressView, 폼 입력 잠금
  • 오프라인 저장: 기기에 저장(savedLocally)하면 시트를 닫고 진행, 서버 동기화는 자동이며 R9 표시로 알림

수용 기준

  • 원두와 마신 날만 넣어도 저장된다
  • 같은 원두의 이전 노트가 있으면 새 노트에 가장 최근 레시피가 채워지고 배너가 보인다
  • 마신 날을 로스팅일보다 이전으로 고르면 저장되지 않고 메시지가 보인다
  • 원두량과 물량을 입력하면 비율이 즉시 1:xx.x로 보인다
  • 축 세그먼트를 바꾸면 오각형이 바로 갱신된다
  • 점수는 0.25 단위로만 입력된다
  • 변경 사항이 있을 때 시트를 쓸어내리면 시트가 닫히지 않고 확인 메뉴가 뜬다
  • 변경 사항이 없으면 쓸어내려 바로 닫힌다
  • 원두 등록(F)에서 돌아와도 작성 중이던 레시피·태그·메모가 그대로 있다
  • 비행기 모드에서 저장하면 시트가 닫히고 목록에 구름 아이콘이 보이며, 연결되면 사라진다

E원두 선택 (D 안에서 push)

목적

노트에 연결할 원두를 고르거나 새로 등록한다.

구성

  • 제목 "원두 선택", .searchable(이름·로스터리)
  • List 첫 섹션: "새 원두 등록" 행(plus.circle) → F push
  • "마시는 중" 섹션: 원두 행 — 이름, 로스터리 · 원산지 요약(블렌드면 "블렌드"), 로스팅일 · 오늘 기준 D+N, 노트 수. 선택된 원두에 체크마크
  • "다 마신 원두" 섹션: 같은 형식
  • 정렬: 최근 노트를 쓴 순 → 노트가 없으면 등록순

동작

  • 행 탭 → 선택하고 D로 pop → R2 적용
  • F에서 저장 → 그 원두를 선택한 상태로 D까지 pop

수용 기준

  • 새 원두를 등록하면 별도 탭 없이 바로 선택된다
  • 다 마신 원두도 선택할 수 있다

F원두 등록 / 편집

표시 방식

E에서 push(툴바 "저장"만, 뒤로 가기는 시스템 Back) 또는 H "+"·I "편집"에서 시트(취소 / 저장). 시트일 때 변경 사항 보호 규칙은 D와 같다.

구성 (Form)

  • 기본: 원두 이름*, 로스터리*(기존 로스터리 이름 자동완성 제안)
  • 원산지 섹션: 구성 원두 행 목록. 각 행은 "에티오피아 · 워시드 · 60%"처럼 요약 표시, 탭하면 구성 편집 화면 push(국가, 지역·농장, 품종, 가공방식 Picker 메뉴, 비율 % — 비율 필드는 구성이 2개 이상일 때만 표시). 행 스와이프로 삭제. 마지막 행 "구성 원두 추가"(5개까지). 구성이 2개 이상이면 섹션 제목 옆에 "블렌드" 배지, 구성 목록 아래 "비율 모름" Toggle(켜면 각 구성의 비율 표시·입력이 사라짐), 꺼져 있으면 footer에 비율 합계("합계 100%", 100이 아니면 danger 색)
  • 구매 용량: g (TextField + .numberPad, 선택)
  • 로스팅: 로스팅 정도(Picker 메뉴 — 라벨이 길어 세그먼트로는 iPhone 폭에 맞지 않음), 로스팅일 "모름" Toggle + DatePicker(.compact)
  • 로스터리 노트(여러 줄)
  • 편집 모드에서만: "다 마신 원두" Toggle, 맨 아래 별도 섹션 "원두 삭제"(destructive 텍스트 버튼, R6)

수용 기준

  • 이름과 로스터리가 없으면 저장되지 않는다
  • 기존 노트의 마신 날보다 늦은 로스팅일로는 바꿀 수 없다
  • 구성을 2개 이상 넣으면 블렌드로 표시된다
  • "비율 모름"이 꺼져 있으면 모든 구성의 비율이 있고 합이 100%여야 저장된다
  • "비율 모름"을 켜면 비율 없이 저장되고 "블렌드 · 에티오피아, 브라질"로 표시된다
  • 원산지를 하나도 넣지 않아도 저장된다
  • 원두 삭제 확인 대화상자에 연결된 노트 수가 나온다

G플레이버 태그 선택

목적

자체 분류 체계(부록)에서 태그를 고른다. 두 가지 모드: 선택 모드(D 안에서 push, 여러 개, 제목 "프레그런스" 또는 "컵 노트") · 필터 모드(B에서 시트, 1개, 제목 "태그로 거르기").

구성

  • .searchable(한국어 이름). 선택 모드에서는 목록 위에 "선택됨 3/10" + 선택된 칩 가로 스크롤(칩을 탭하면 해제, 칩 높이 32pt + 터치 영역 44pt)
  • 첫 단계: 계열 8개를 색상 타일 2열 그리드(타일 높이 64pt 이상)로 표시 → 탭하면 그 계열 목록으로 push
  • 하위 목록(List): 맨 위 행 "‘과일’ 전체" — 그 단계 자체를 선택(체크마크). 그 아래 하위 행 — 하위가 있으면 행 전체가 push(disclosure indicator, 하위 선택이 있으면 오른쪽에 선택된 이름을 강조색으로), 하위가 없으면 행 전체가 선택 토글(체크마크). 한 행에 탭 영역을 둘로 나누지 않는다
  • 검색 중에는 계층 대신 일치하는 노드를 평평한 목록으로, 경로를 보조 텍스트로 표시 (예: 블루베리 — 과일 › 베리). 모든 결과 행은 선택 토글

동작

  • 선택 규칙은 R5
  • 10개를 선택하면 선택하지 않은 행은 흐리게 비활성화하고, 목록 상단 문구를 "10개까지 고를 수 있어요"로 바꾼다(토스트 대신 인라인 안내 + 경고 햅틱)
  • 선택 모드: 변경 즉시 D에 반영, 시스템 Back으로 돌아감. 필터 모드: 탭 즉시 적용하고 시트 닫힘, 툴바 왼쪽 "취소"

수용 기준

  • 1·2·3단계 어느 것이든 선택할 수 있다
  • "블루베리"를 고르면 같은 목록에서 이미 고른 "베리"와 "과일"은 해제된다
  • 프레그런스와 컵 노트에서 같은 태그를 각각 고를 수 있다
  • 검색 결과에 경로가 함께 보인다
  • deprecated 태그는 목록에 나오지 않지만, 기존 노트에서는 계속 보인다

H원두 목록 (원두 탭 홈)

구성

  • Large Title "원두", 툴바 오른쪽 "+"(plus, 라벨 "원두 등록") → F 시트
  • 목록 위 Picker(.segmented): 마시는 중 / 다 마심, .searchable
  • 원두 카드 행: 이름, 로스터리, 원산지 요약(블렌드면 "블렌드 · 에티오피아 60% / 브라질 40%"), 로스팅일 · 오늘 기준 D+N, 노트 수, 평균 점수(점수 있는 노트만), 최근 노트의 오각형(60pt)
  • 스와이프: "다 마심" 토글(leading), "삭제"(trailing, R6). 길게 누르기: 편집, 이 원두로 노트 쓰기, 삭제

상태

  • 빈 상태: ContentUnavailableView "원두를 등록하면 여러 잔의 기록을 한곳에 모을 수 있어요" + "원두 등록"

수용 기준

  • 평균 점수는 점수가 있는 노트만으로 계산하고 소수 둘째 자리까지 표시한다
  • 노트가 없으면 평균 점수와 오각형 대신 "아직 노트가 없어요"가 보인다

I원두 상세

목적

같은 원두를 여러 번 마신 기록을 시간순으로 비교한다(F6의 핵심 화면).

구성

  1. 원두 정보 섹션(F의 모든 값: 구성 원두 목록, 구매 용량 포함), 로스터리 노트
  2. 요약: 노트 수, 평균 점수, 최고 점수
  3. 기록 표: 열 = D+N · 마신 날 · 점수 · 드리퍼 · 분쇄도 · 비율 · 재구매. 행 = 노트(D+N 오름차순). 행 탭 → C. 접근성 크기에서는 표 대신 행별 카드로 전환
  4. 노트 카드 목록: 각 카드에 오각형(88pt) + 태그
  5. 하단 .safeAreaInset(edge: .bottom)에 주 버튼 "이 원두로 노트 쓰기"(.borderedProminent, .controlSize(.large)) → D 시트

동작

  • 툴바 "편집" → F 시트

수용 기준

  • 기록 표는 D+N 오름차순이다. 로스팅일이 없으면 마신 날 오름차순이고 D+N 열은 "—"
  • "이 원두로 노트 쓰기"로 연 노트에는 최근 레시피가 채워져 있다

J설정

구성 (Form, .insetGrouped)

  • 계정 섹션 — 익명: "Apple로 계속하기" → A, footer "Apple 계정에 보관하지 않으면 앱을 지우거나 기기를 바꿀 때 기록이 사라져요. 예전에 보관한 기록도 여기서 불러올 수 있어요." / Apple 연결됨: "Sign in with Apple 사용 중" + 이메일(가려진 릴레이 주소일 수 있음), "로그아웃"
  • 기록 섹션: "내 장비" → K push (오른쪽에 등록 개수)

  • 계정 삭제 후 같은 Apple 계정으로 로그인하면 빈 상태로 시작한다
  • 삭제 후 Firestore에 users/{uid}와 beans·notes·gear 문서가 하나도 남지 않는다
  • 삭제 도중 네트워크가 끊겨도 다시 시도하면 끝까지 삭제된다

K내 장비 / 장비 선택

목적

드리퍼(추출 기구)와 그라인더를 관리하고, 레시피에서 고른다. 두 가지 모드: 관리 모드(J에서 push) · 선택 모드(D의 드리퍼·그라인더 행에서 push, 해당 종류만 표시).

구성

  • 관리 모드: 제목 "내 장비", 툴바 "+"(plus, 라벨 "장비 추가") → L 시트. List 섹션 "드리퍼·추출 기구" / "그라인더". 행: 이름, 그라인더면 보조 텍스트로 단위("클릭"), 이 장비를 쓴 노트 수
  • 선택 모드: 제목 "드리퍼 선택" / "그라인더 선택". 첫 행 "선택 안 함", 이어서 장비 행(선택된 행에 체크마크), 마지막 행 "새 드리퍼 추가"(plus.circle) → L push

동작

  • 관리 모드: 행 탭 → L(편집) push, 스와이프 "삭제" → 확인 대화상자 "과거 노트에는 장비 이름이 남아요"(D31)
  • 선택 모드: 행 탭 → 선택하고 D로 pop. L에서 저장하면 그 장비를 선택한 상태로 D까지 pop

상태

  • 빈 상태(관리 모드): ContentUnavailableView "드리퍼와 그라인더를 등록하면 분쇄도를 정확히 기록할 수 있어요" + "장비 추가"

수용 기준

  • 선택 모드에서는 고르려는 종류의 장비만 보인다
  • 노트 작성 중에 새 장비를 추가하면 바로 선택된다
  • 장비를 삭제해도 그 장비를 쓴 과거 노트에 이름이 남아 있다

L장비 등록 / 편집

표시 방식

K 관리 모드의 "+"에서는 시트(취소 / 저장), 그 밖에는 push(저장만).

구성 (Form)

  • 종류: Picker(.segmented) 드리퍼·추출 기구 / 그라인더 (선택 모드에서 들어오면 종류 고정)
  • 이름*(예: "하리오 V60 02 세라믹", "코만단테 C40")
  • 그라인더일 때만: 분쇄도 단위(예: "클릭", 기본값 "클릭")
  • 메모
  • 편집 모드: 맨 아래 "장비 삭제"(destructive, K와 같은 확인)

수용 기준

  • 이름이 없으면 저장되지 않는다
  • 그라인더의 분쇄도 단위를 바꾸면 그 그라인더를 쓴 노트의 분쇄도 표시도 바뀐다
