# 04. CI — GitHub Actions

## 개념
**CI(Continuous Integration)**: 코드를 올릴 때마다 서버가 자동으로 빌드·테스트해서 "main은 항상 동작한다"를 지키는 장치. PR 화면에 ✅/❌로 표시된다.

## 이 프로젝트의 CI (`.github/workflows/ci.yml`)
두 개의 job이 병렬로 돈다.

| job | 러너 | 하는 일 |
|---|---|---|
| `ios` | macOS | XcodeGen으로 프로젝트 생성 → 시뮬레이터에서 단위 테스트 |
| `firebase` | Ubuntu | Node·Java 설치 → Functions 빌드·타입 검사 → Emulator에서 규칙 테스트 |

- `on: pull_request` — 모든 PR에서 실행. `on: push: branches: [main]` — 머지 후에도 한 번 더.
- `concurrency` — 같은 브랜치에 새로 push하면 이전 실행을 취소해 시간을 아낀다.
- 실패하면 iOS 테스트 결과(`.xcresult`)를 아티팩트로 올려 내려받아 Xcode에서 열어 볼 수 있다.

## 로컬에서 같은 검사
CI가 실행하는 명령은 `scripts/`의 스크립트와 같다. push 전에 `scripts/test-ios.sh && scripts/test-firebase.sh`로 미리 확인하면 CI 실패를 줄일 수 있다.
